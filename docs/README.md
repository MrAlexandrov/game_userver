## 🎮 Основной игровой процесс

```
1. Создание пака вопросов
   POST /packs/yaml
   
2. Создание игровой сессии
   POST /games
   
3. Добавление игроков
   POST /games/{id}/players
   
4. Старт игры
   POST /games/{id}/start
   
5. Игровой цикл:
   - GET /games/{id}/state (получить вопрос)
   - POST /games/{id}/answers (отправить ответ)
   - Повторять для каждого вопроса
   
6. Получение результатов
   GET /games/{id}/results
```

Подробнее: [GAME_FLOW.md](GAME_FLOW.md)

## 🔑 Ключевые концепции

### Observer Pattern

Система использует паттерн Observer для уведомления о игровых событиях:
- Создание игры
- Добавление игрока
- Отправка ответа
- Завершение игры

Подробнее: [OBSERVER_PATTERN.md](OBSERVER_PATTERN.md)

### Singleton GameService

GameService - единственный экземпляр на весь сервер:
- Сохраняет observers между запросами
- Обеспечивает консистентность состояния
- Улучшает производительность

Подробнее: [BACKEND_ARCHITECTURE.md](BACKEND_ARCHITECTURE.md#singleton-components)

### Типы вопросов

Система поддерживает разные типы вопросов:
- `multiple_choice` - выбор из вариантов
- `free_text` - свободный ответ
- `custom` - кастомная логика валидации

Подробнее: [API_REFERENCE.md](API_REFERENCE.md#question)

## 📊 Состояния игровой сессии

```
waiting → active → finished
```

- **waiting**: Ожидание игроков, можно добавлять игроков
- **active**: Игра идет, игроки отвечают на вопросы
- **finished**: Игра завершена, доступны результаты

Подробнее: [DATA_FLOW.md](DATA_FLOW.md#состояния-и-переходы)
